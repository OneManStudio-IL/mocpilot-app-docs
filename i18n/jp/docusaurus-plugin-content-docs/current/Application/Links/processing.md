# 処理 {#processing}

処理ブロックは入力と動作の間に置き、途中で値を変えます。1 つの行に置く処理ブロックは、なし、1 つ、複数のいずれでもよく、順序も自由です。設定と指定できる値：[処理ブロック](/docs/Application/Links/Blocks/ProcessingBlocks)。

| ブロック | 働き |
|---|---|
| [反転](/docs/Application/Links/Blocks/ProcessingBlocks#mod-invert) | 方向を逆にする、またはオンとオフを入れ替える |
| [制限](/docs/Application/Links/Blocks/ProcessingBlocks#mod-limit) | 値の上限を決める |
| [デッドゾーン](/docs/Application/Links/Blocks/ProcessingBlocks#mod-deadzone) | ゼロ付近の小さな動きを無視する |
| [しきい値](/docs/Application/Links/Blocks/ProcessingBlocks#mod-threshold) | 値をオン/オフに変える |
| [スムーズ](/docs/Application/Links/Blocks/ProcessingBlocks#mod-smooth) | 徐々に加速・減速する |
| [トグル](/docs/Application/Links/Blocks/ProcessingBlocks#mod-toggle) | 1 回押すとオン、もう一度押すとオフ |

## 反転 {#invert}

モーターが逆に回る？モデルを組み直さずに **反転** を追加しましょう。逆方向に回す必要がある 2 つのモーター（左右のクローラー、ギアボックスの両側）には、同じ入力から 2 つの行を作り、片方に反転を入れます。

## 制限 {#limit}

モデルを遅くして操作しやすくします。**最大** を 50 % にすると、スティックをいっぱいに倒しても速度は半分になります。子ども向け、室内での走行、繊細な機構に向いています。

## デッドゾーン {#dead-zone}

ジョイスティックはぴったりゼロで止まることがほとんどないため、モーターがうなったり、少しずつ動いたりすることがあります。**デッドゾーン** は小さな値をゼロとして扱います。まずは 10 % がおすすめです。

## しきい値 {#threshold}

値をオン/オフに変えます。「値が 20 % を **上回る** とオン」のように使います。センサーと組み合わせた *距離センサー* → *しきい値*（下回る、20 %）は、何かが近づくとオンになります。しきい値には少しヒステリシスがあるので、境目でちらつきません。

## スムーズ {#smooth}

実際の車両のように、徐々に動き出して止まります。加速と減速は別々に設定します。重いトラックなら、加速に 2 秒、停止に 0.5 秒といった具合です。ライトに使うと、スムーズにフェードイン・フェードアウトします。

## トグル {#toggle}

ボタンをスイッチに変えます。1 回押すとオン、もう一度押すとオフです。*ボタン* → *トグル* → *ライト*。

## ヒント {#tips}

- 順序が大切です。走行には *デッドゾーン → 制限 → スムーズ* の組み合わせがおすすめです。
- 信号に合わないブロックははまりません。トグルにはオン/オフの入力が、デッドゾーンとしきい値には値が必要です。
- プログラムの実行中にライブ値を見ると、各ブロックの働きがわかります。
